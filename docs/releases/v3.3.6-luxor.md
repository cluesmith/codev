# v3.3.6 Luxor

Released: 2026-10-29

## Summary

3.3.6 is a Luxor patch that grew. It started as the process behind the Decisions tab and
now also carries the work that landed on main while it waited: agents report their own
attention state to Tower instead of having it guessed from silence; `codev bootstrap-docs` drafts the
governance docs for a project adopting Codev on a mature codebase; Jira joins Linear as an
issue tracker; and a builder worktree opened in VS Code no longer becomes a second workspace.

This release also publishes the VS Code extension to the Marketplace for the first time
since 3.3.4. Extension 3.3.6 therefore carries every extension item announced in the
v3.3.5 notes (the Tower view, the review queue in the contextual panel, Restricted Mode
activation, the reading aids, the 1.128 floor) together with the items below.

## The owner decisions process (#1826, PR #1832)

`resources/decision-protocol.md` now ships in the Codev skeleton. It describes the loop end
to end:

- **One file, one hub.** Every ask for the owner's word is one item in
  `codev/state/pending-decisions.md`; one architect named `main` is the hub and the only
  agent that edits the file. Other architects send items with
  `afx send architect:main 'DECISION <name>-<n>: <question> …'`.
- **The item.** A `###` heading of id, time stamp with its zone, and the question; a short
  body of labelled lines (Problem, Options, Fix, Testing, Recommendation, Links); and one
  `**Your word:**` line whose backticked, `/`-separated words become the card's buttons, the
  first one marked as recommended.
- **What the tab reads.** The exact parsing rules: which headings are items, which zones the
  stamp converts from, how a bare word takes its description from the `**Options:**` line,
  and how a question-and-answer thread shows on the card.
- **What the hub does.** Post, learn of rulings (from the tab, the file or chat), answer
  questions, relay `RULING <id>: <word>` to the asking architect with the owner's comment
  carried verbatim, record the ruling and its `DONE` line under `## Ruled`, and scan the file
  on every resume.

The architect role gained a three-line pointer to the document, and the Tower command
reference links it from its Decisions tab section. A new test runs the document's own
fenced examples through the Decisions tab's parser, splicer, notice builder and stamp
resolver, so the document cannot drift from the code without failing CI.

The document resolves from the installed package: `codev init`, `adopt` and `update` do not
yet copy skeleton reference documents into an adopter's `codev/resources/`. Until #1834
lands, read it in the package under `skeleton/resources/decision-protocol.md`, or on GitHub
at `codev-skeleton/resources/decision-protocol.md`.

## Turning the tab on: `afx decisions init` (#1840, PR #1841)

One command creates the decisions file from its template and turns on the Decisions tab:

```bash
afx decisions init
```

It writes `codev/state/pending-decisions.md`, or the path `dashboard.decisionsFile` names,
prints where the file went, and gives the one sentence to tell the main architect: "Route
every ask for my word through the decisions file." It never replaces an existing file, which
holds the owner's rulings, and it refuses a path outside the workspace, the same rule the tab
applies. The template lives once in the code and the protocol document is pinned to it by a
test. The architect role now says: when the owner asks to use decisions, run the command and
follow the document.

## Stamps: everything in UTC, shown in your time (#1836, PR #1837)

Nearly every card used to carry "Not converted: the date or time is not in a recognized
format", because the tab accepted only a full stamp with date and zone and hubs wrote a bare
time or none. Now:

- Agents write every time in UTC, `YYYY-MM-DD HH:mm UTC`, and the tab shows it in each
  viewer's own time. The file template carries a `_Zone: UTC_` line.
- A stamp with no zone takes the file's zone; a bare time is read as today in that zone and
  the card shows the converted time alone, with no date nobody wrote.
- A heading with no stamp, or one the tab cannot read, keeps its question and shows no warning.
  The warning remains only for an ambiguous zone such as `IST` and for a clock time that was
  skipped or repeated.

Anything a person types in another zone still converts. Follow-ups: a bad `_Zone:` line
reported once at the top of the tab (#1838); the Ruled list and question-and-answer lines
converted to the viewer's time as well (#1839).

## A builder worktree is no longer a workspace of its own

A builder's worktree contains the whole repository, so opening one as a folder made Codev activate it as a separate workspace (#1809, PR #1846): it recorded the worktree as a known workspace, started an architect for it, and the rows piled up over time with nothing to clear them. Because such a window reads the parent checkout's data, it also surfaced the parent's lanes: gate notifications for other lanes, each carrying an Approve button that would have approved that lane's gate, along with builder counts, the sidebar badge, the attention list, and spawn notifications that could open another lane's terminal.

A worktree window now attaches to its parent checkout read-only and never activates it. The Agents view is absent, the parent's notifications, counts and badge stay with the parent's own window, the contextual panel is pinned to the worktree's own builder, and the Workspace view keeps only its dev rows. Reviewing files in that window, comments included, is unchanged.

On the operator side, Tower refuses to activate a builder worktree and points at the parent instead, and it clears worktree rows left by earlier windows when it starts. A worktree window that is still running is reported rather than stopped: the message names how to stop it, and for one Tower cannot reach it gives the process id instead. Starting Codev logs one line with the counts.

Known and expected: the Agents view can paint briefly as a worktree window loads, before it disappears.

## Governance docs drafted from the codebase: `codev bootstrap-docs` (#1797, PR #1808; #1811)

A project that adopts Codev on a running codebase starts with the four governance docs as placeholders, and nothing filled them in. `codev bootstrap-docs` now does: it launches your agent (Claude Code or Codex) in a session that works in the update-arch-docs skill's bootstrap mode, surveys the build wiring, entry points, service boundaries and persistence, explores the history (the project's own record first, then one line per PR, older eras, fixes and reverts, what was removed), and drafts only the files that are still placeholders. Curated files are read, never edited. When the session ends, Codev validates the drafts against the hot-tier caps, reports anything that changed outside the eligible files, and sends the drafts to the three reviewers for feedback. Nothing is committed for you. `codev adopt` offers the run when it finishes, and `codev update` says when the docs are still placeholders.

The agent follows the project's installed skill when it matches the package, so the rules it writes to are the rules the drafts are checked against. That needed `codev update` to keep skills current (#1811): a shipped skill you never edited is now replaced with the package's version, matched against every version Codev has shipped; an edited one keeps your content and gets a `.codev-new` copy of each changed file for the merge session, the same treatment CLAUDE.md gets. An empty skill folder is filled. `codev update --dry-run` now previews all of this and writes nothing; it used to write `CLAUDE.md.codev-new` and `AGENTS.md.codev-new` during a dry run. Symlinked skills, governance paths and `.codev-new` copies are never written through.

## Agent attention states from the harness (#1595, PR #1854)

Tower now learns an agent's state from the agent itself. Claude builders and architects report turn start, tool activity, permission prompts, questions and turn end through a fail-open hook, and Tower fuses that with process liveness to serve working, needs-input, idle, blocked or dead on the overview. The VS Code extension (Agents view, Tower view, status bar, badge) and the dashboard (builder card, Needs Attention list) show the same state from one shared rule. A permission prompt is counted the second it is drawn; a silent long-running tool stays working; an exited agent reads dead within about ten seconds. Codex and OpenCode builders, and Claude sessions started before the update, keep the previous silence-based behaviour. Attention state lives in Tower memory only and is rebuilt from the agents' next reports after a restart. Known gap: an approved long-running tool stays at needs-input until it finishes (#1851).

## Jira as the issue tracker (#1740, PR #1848)

Codev can now run a project whose issues live in Jira Cloud while the code stays on GitHub. Set `"forge": {"provider": "jira"}` in `.codev/config.json`, with `jira-site` and optionally `jira-project`, and log in once with Atlassian's `acli`; Codev never reads or stores a Jira token. The Jira preset covers viewing, listing and searching issues, commenting, recently closed items and the current user, and every PR operation keeps running through `gh`, the same hybrid shape Linear uses. `codev doctor` reports both logins for Jira and Linear workspaces, and no longer warns about the provider's own settings.

Tracker keys such as `ENG-123` now carry through everything that used to assume a number: `afx spawn`, worktree and branch names, porch project ids, PR linking (`[PIR #ENG-1]`, `Fixes #ENG-1`), builder lookup and cleanup, the overview, the dashboard and the VS Code extension. Numeric ids resolve exactly as before, because every numeric pattern is still tried first, and the overview now prefers the issue id it stored at spawn time over parsing a folder name. A random short id for an issue-less spawn can no longer take the shape of a key. Closing a Jira issue when its PR merges stays a manual step: GitHub's closing keywords do nothing for a Jira key.

## Other fixes (dashboard, porch, infrastructure)

- **The Decisions tab sits second, right after Work** (#1861, PR #1862). It holds the owner's pending rulings, the most time-sensitive thing on the dashboard, and used to sit behind Analytics and Team.

## Breaking changes

- **Published types: `createdAt` is now optional on backlog and issue-search items, and `OverviewData.issueIdKind` is new** (#1740, PR #1848). Jira's search cannot return dates, so consumers of `@cluesmith/codev-types` (the Stream Deck plugin and the client SDK) must treat a missing `createdAt` as unknown rather than a date.

## Upgrade

```bash
npm install -g @cluesmith/codev@3.3.6
afx tower stop && afx tower start
```

The VS Code extension ships separately via the Marketplace: `Codev` by `cluesmith`, version
3.3.6, the first Marketplace release since 3.3.4. Nothing changes for a workspace without a
decisions file: the tab appears only when the file exists, and the hub notice goes only to an
architect named `main`.
