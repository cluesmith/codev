# Spike: afx send input corruption — line-occupancy detection & non-destructive delivery (#1265)

**Date**: 2026-07-30 (updated 2026-07-31 after review rounds 2–9)

**Verdict**: **Feasible** — the recommended combination (A+E core, H for max-age, per-app atomic delivery) is validated empirically against both target TUIs, with significant revisions accumulated over nine review rounds: **Option I is app-specific** (claude wants the *unbracketed* atomic form, codex the *bracketed* one — each fails with the other's form), the issue's proposed composing clear-set was wrong on two keys (ESC, Ctrl+G), **H is best-effort and journal-backed** (constraint 8) **with a bounded, specifiable divert window** — bulk/line-chunked writes replace char pacing (round 9, `i7`) — **and an explicit phase-2 build/skip gate** (its addressable population is narrower than the option list implies), **K's hold core must ship in the first phase** so no force-inject path ever survives (round-6 phasing), **dirty→clean convergence is an output-side proof with no keystroke required** (round 8: builder terminals have no human typist; the G-lite check runs on the production ring-replay data path, validated by `g2*`), and — round 9 — **the rendered-empty check is the universal pre-delivery gate, not just the dirty exit**: the builder launch-loop wrapper is a measured silent-loss path that input-side tracking cannot see (`i8`), **every session starts dirty** (fresh spawns render onboarding/trust Enter-traps), and **delivery forms key on a strict app-identity allowlist** — today's harness resolver falls back to claude and would aim claude's atomic form at unknown apps.

## Question

Issue #1265: `afx send` can land in the middle of a half-typed draft and submit the blob as one message, because the defer decision uses a 3s idle timer (`isUserIdle`) instead of real line-occupancy. The issue proposes options across detection (A/E/F/G), delivery (B/C/H/I/J), and channel (D/K/L) axes, recommending **A+E** core, **H** for the 60s max-age case, **J** framing, **I/K** hardening. This spike answers the empirical unknowns analysis could not settle, **against the real Ink-based TUIs** (Claude Code 2.1.212 throughout; Codex 0.145.0, bumped to 0.146.0 mid-spike — the asserted codex suite was re-run green on 0.146 in round 8, exploratory-tier codex measurements remain 0.145), and gives a go/no-go per building block.

Method: a node-pty + `@xterm/headless` harness (`codev/spikes/1265-poc/`, emulator pinned at `@xterm/headless` 6.0.0 — every run's `.out` records the version) spawns the actual `claude`/`codex` binaries, injects keystroke bytes exactly as Tower's `session.write()` does, and asserts on the *rendered* composer. Evidence tags (`b3`, `p4`, …) refer to the `exp-*.cjs` experiments there; `p*` tags are the end-to-end max-age sequence (`exp-i5-maxage-fullseq.cjs`, added after review flagged the kill-ring interaction), `i6*` tags are the integration-semantics demos (`exp-i6-gating.cjs`, review round 3: input gating, flush ordering, menu/modal Enter-ambiguity; the flush-ordering cases were re-isolated and re-asserted in round 5; the codex arm runs only the `i6c` menu demos, 2 of the 11 assertions — `i6a`/`i6b` need the dead-API submission rig and are claude-only), `w1*` tags are Tower-side writer-scheduling demos (`exp-w1-writer-race.mjs`, round 5) that drive the **real `message-write.ts` production module** at unit level — no TUI involved, because the behavior under test is Tower's own scheduling, `g2*` tags (`exp-g2-glite-prod-path.mjs`, rounds 8–9) drive the **real `RingBuffer` production class** plus the exact client replay join (`tower-websocket.ts:66-67`) into a transient `@xterm/headless` instance — the production G-lite data path — with the classifier verdicts asserted against the live screens the TUIs actually rendered (round 9 extended the codex arm from 7 to 25 assertions: menu, model-picker, nudge-draft, nudge-empty, churn+byte-cut; and added claude nudge-empty plus reconstruction cost timings at 1 MB/4 MB), `i7*` tags are the bulk-replay maneuver timings (`exp-i7-bulk-replay.cjs`, round 9 — bounds H's divert window), and `i8*` tags are the launch-loop wrapper loss demos (`exp-i8-wrapper-loss.cjs`, round 9 — the production `LAUNCH_LOOP_TAIL` is extracted from `spawn-worktree.ts` at runtime so the wrapper under test is the shipped one). Submission-heavy tests ran claude against an unroutable `ANTHROPIC_BASE_URL` (full submit mechanics, zero API calls). Codex ignores base-URL overrides under ChatGPT OAuth, so codex submissions used only the local `/status` command (plus three accidental tiny prompts, lesson learned below).

## Keystroke → occupancy classification (measured)

| Key | Claude Code 2.1.212 | Codex 0.145.0 | Tracker action |
|---|---|---|---|
| printable | occupies | occupies | append to draft buffer (exception: leading `/` on an empty buffer opens the slash menu → **mode: dirty**) |
| bare `\r` | **submits** (composer clears) | **submits** | clear buffer; **flush trigger (E)** |
| `\x1b\r` (Alt+Enter) | newline in draft | newline in draft | append newline — **NOT submit** |
| `\n` (Ctrl+J) | newline in draft | newline in draft | append newline — **NOT submit** |
| `\\` then `\r` | newline in draft (continuation) | **submits** (`ccc\` went to the model) | treat as non-submit (safe direction: worst case is deferral, not corruption) |
| Ctrl+U | kills **[line-start, cursor)** — clears the whole line only when the cursor is at end (`a3a`: `abcdef`+Left×3+Ctrl+U → `def`, both TUIs; round-1 "kills whole line" was an end-cursor artifact) | same | cursor-aware delete `[0, cursor)`; if cursor position is unmodeled → **dirty** |
| Ctrl+C | clears draft (⚠ arms exit when line already empty — unsafe as an *injected* primitive) | clears draft | clear buffer; **if the model was already empty → mode: dirty** (the arm-exit state precedes the deliberate-quit → launch-loop wrapper prompt, constraint 10/`i8`; a second `^C` kills the agent, #1264) |
| ESC ×1 | nothing ("Esc again to clear") | nothing | occupancy: no-op; **mode: dirty** (interrupts in-flight turns; queued-restore and edit-last-message hazards — constraint 4c/d) |
| ESC ×2 | clears draft (⚠ opens rewind/queued-edit overlays when composer empty) | does **NOT** clear | app-dependent — unusable as a portable clear; **mode: dirty** |
| **Ctrl+G** | **opens $EDITOR (vim) with draft** | **same** | ⚠ modal — must NOT be in any clear-set (issue proposed it; wrong) |
| Up | occupies (history/queued recall, `e2`) | occupies — recalls even **cross-session persisted** input | mark composing (genuinely occupies); **mode: dirty** (recall/queue-edit overlays) |
| Down | may return to empty | may return to empty | keep composing (conservative); **mode: dirty** |
| Tab | hint only, line unchanged | line unchanged | occupancy: neutral — do not set composing (was a #492 stuck-true source); **mode: dirty** — Tab is context-dependent (e.g. claude `@`-mention completion) and the measured "hint only" was the plain-text context |
| Left/Right | cursor only | cursor only | move the **modeled cursor** (content unchanged) |
| Backspace | deletes **at the cursor**, not the tail (`a3b`: `abcdef`+Left×2+BS → `abcef`, both TUIs) | same | cursor-aware delete at `cursor-1` (model-empty ⇒ not composing) |

The table carries **two orthogonal state axes** (reconciled in round 7): **occupancy** — does the composer hold text — drives A's defer and E's flush, and here Tab/ESC are genuinely *neutral* (the #492 lesson: treating them as composing caused the stuck-true bug); and **mode confidence** — could a menu/overlay be consuming keys — drives the dirty machine, and here ESC/Tab/Up/Down/leading-`/` are *suspects* (constraint 4). "Occupancy-neutral" never implies "safe to inject": injection safety requires clean on **both** axes.

**Key insight that simplifies the design**: H's per-session capture **subsumes A's boolean** — but round 4 showed the tracker needs **two separate structures**, because Ctrl+U/Backspace are cursor-relative (`a3`):
1. a **raw replay log** (the verbatim byte stream — ground truth for H's replay; editing keys replay faithfully so modeling errors can never corrupt a replay), and
2. a **modeled line state** (per-line text + cursor position, maintained over printables/Left/Right/Home/End/Ctrl+E/Backspace/Ctrl+U/newline gestures) that answers "is the composer empty?" for A's defer decision and E's flush trigger. A naive "clear buffer on Ctrl+U" model declares `abcdef`+Left×3+Ctrl+U empty while the line still shows `def` — delivery onto an occupied line, the original corruption. Any byte the model can't confidently apply → **dirty** → defer + K.

One `DraftTracker` — tapped at `PtySession.write()` so every writer feeds it (integration constraint 5) — carries both structures and powers all three: the defer decision (A), the flush-now event (E: model transitioned to empty via bare `\r`/Ctrl+C/emptying edits), and the replay payload (H). The per-line clear maneuver is immune to the cursor issue by construction: its `^E` prefix moves to end-of-line before each `^U`, which is exactly why `^E ^U` clears a line from any cursor position (`a3c`).

## Submit-detector hazards (for E)

Today's `tower-websocket.ts:96` heuristic (`data.includes('\r') || data.includes('\n')` ⇒ stopComposing) is wrong in both directions:
- **False submit** (would flush mid-draft — the corruption we're fixing): Alt+Enter frames (`\x1b\r`), Ctrl+J (`\n`), backslash-continuation `\r` (claude), and `\r`/`\n` inside bracketed-paste content (user pasting a multi-line draft).
- Correct rule: submit ⇔ frame is bare `\r` (or `\r` not preceded by `\x1b` in-frame, not inside `ESC[200~…201~`, previous frame not ending in `\\`). Kitty-protocol Enter (`\x1b[13u` style, if a client terminal ever sends it) should also be matched; missing it only degrades to max-age deferral (safe direction).
- Even a correctly-classified bare `\r` is only a submit **when no menu/mode is open** (`i6c`) — the dirty-state machine in the integration constraints governs when the flush may actually fire.
- **Ordering**: the flush must write the message strictly *after* the user's Enter byte has been written to the PTY — the current handler tracks before `session.write(data)`, and flushing from there submits the blob (`i6b`; integration constraint 3).

## Delivery matrix (for the max-age / busy-line path)

Two **non-overlapping** paths, selected by whether the captured draft is single- or multi-line. The trailing `^Y` is the *single-line restore mechanism* and must appear **only** there — on the multi-line path the byte-replay is the restore, and a trailing `^Y` measurably corrupts it (see the kill-ring constraint below and `i5`).

**Single-line drafts — kill/yank restore (Options I/B). Form ENDS in `^Y`:**

| Target | Verified atomic form | Result |
|---|---|---|
| claude | `^E ^U` + msg (raw, multi-line msg ok) + `\r` + `^Y` — one write | message submitted intact, draft restored by the yank, user bytes cannot interleave (`b3`, `i4`) |
| codex | `^E ^U` + `ESC[200~` msg `ESC[201~` + `\r` + `^Y` — one write | same (`i2a`) |

**Multi-line drafts — H byte-replay restore. NO trailing `^Y` anywhere:**

| Target | Verified sequence | Result |
|---|---|---|
| claude | per-line clear `(^E ^U BS) × N` → `^E ^U` + msg + `\r` (one write, **no `^Y`**) → byte-replay | draft reconstructed byte-identical (`p5`, claude) |
| codex | per-line clear `(^E ^U BS) × N` → `^E ^U` + `ESC[200~` msg `ESC[201~` + `\r` (one write, **no `^Y`**) → byte-replay | same (`p5`, codex) |
| unknown app | **no injection form — defer-only + K** (the `i2b`/`j2` semi-atomic shape stays validated as a *future onboarding recipe* for apps that pass the matrix, not a default) | Round 9 hardened this from hygiene to mechanism: (a) there is **no substrate that can even name an unknown app** — `detectHarnessFromCommand` matches only claude/codex/gemini/opencode basenames and `resolveHarness` **falls back to `CLAUDE_HARNESS`**, so keying delivery on today's resolver would aim claude's atomic form at agy (see Constraints); (b) agy's fresh-spawn trust dialog is an Enter-trap (`exp0c` round 8) — since cleared for THIS workspace (round 9 re-run: normal `> ` composer, typed text renders, `^E ^U` clears), but trust is per-folder, so fresh worktrees re-trap; (c) agy's `>` marker doesn't match the G-lite profile → it can never classify clean → automatically held. Defer-only + K is the only safe default. |

On the multi-line path, N comes from the captured buffer's newline count + harmless slack rounds (extra Backspace on an empty composer is a no-op). The kill/yank restore is off the table for multi-line (`b4`: `^U` kills only the current line).

**Maneuver pacing — bulk writes, measured (round 9, `i7`).** i5 validated the sequence under char pacing (50 ms per clear step, 14 ms per replayed chunk), which is linear in draft size: ~14 s at 1 KB and ~2 min at an 8 KB capture — an unboundable divert window (the round-8 "~2 s" was the 3-line case, and the matrix's older "few hundred ms" was flat wrong). Measured per step, per app: **bulk clear** (all `(^E ^U BS)` rounds in ONE write) empties in ~100 ms on claude up to 13 rounds and on codex up to 41 rounds, but **claude does not complete a 41-round bulk clear** (condition-polled 4 s; the paced 150 ms/line form from `i5` is the validated claude fallback); **bulk replay** (the whole captured stream in ONE write) reconstructs byte-identically in ~100 ms on claude at 138 B/552 B/**1.8 KB**, and on codex at 138 B/552 B — but **codex paste-collapses the 1.8 KB single write** into a `[Pasted Content 1002 chars]` attachment (content preserved, rendered composer NOT restored — a replay failure for H's contract); codex's validated large-draft form is **line-chunked replay** (one write per captured line segment, 40 ms apart — 3.2 s at 40 lines). Net: every step is O(1) writes for typical drafts (≤12 lines ⇒ whole maneuver ~1–3 s including verify settles) and O(lines) in the per-app fallback form at size (~40-line worst case ≈ 7 s claude / 3.5 s codex), so the fail-open gate timeout is **specifiable as f(app, lines)** — e.g. 2× the computed budget — instead of unspecifiable as before. The failure modes are *opposite* per app (claude: clear stalls at size, replay bulks fine; codex: clear bulks fine, replay collapses at size) — one more instance of the per-app-divergence constraint, and more weight behind version-pinning the delivery matrix. The 8 KB capture cap stands, now bounded either way. Measured en route: tall drafts **scroll** the composer (claude windows at 12 lines; codex somewhere past 12) — the rendered composer is a *window*, so ref/verify equality and G-lite verdicts operate on the window, which is exactly what a screen-level check can promise.

⚠ **The maneuver runs as a transaction on the per-session write queue, with user input diverted** (integration constraint 7 generalizes this beyond H), **and only after the capture buffer is journaled to disk** — a crash or fail-open timeout between clear and replay must surface the journaled draft as held bytes, never lose it (constraint 8). User keystrokes are currently written straight through to the PTY (`tower-websocket.ts:101`), so without a gate a keystroke arriving mid-maneuver interleaves with the clear/inject/replay byte stream. Measured (`i6a`): a `Z` arriving between inject and replay, with the naive "also append it to the replay" policy, appears **twice** (`Zfirst line\n second lineZ`). During the maneuver, Tower must **divert** that session's user input frames into the capture queue instead of writing them, then append them after the replay — the diverted-and-appended variant reconstructs `draft + Z` exactly (`i6a` gated run). The gate is short-lived (~1–3 s for typical drafts with bulk writes, O(lines) in the per-app fallback forms — `i7`, see "Maneuver pacing") and must fail open on a timeout so a wedged maneuver can never eat input.

### Kill-ring interaction (measured — do not re-introduce)

The per-line clear **primes the kill-ring**: it kills bottom-up and consecutive kills **overwrite** (not accumulate) on both TUIs, so after clearing an N-line draft the ring holds exactly the **first draft line** (`p3` ring probe, identical on claude and codex). Chaining the single-line atomic form (which ends in `^Y`) after that clear yanks the stale line onto the fresh prompt before the replay lands — measured outcome on **both** TUIs (`p4`):

```
before:  first line\n  second line\n  third
buggy:   first linefirst line\n  second line\n  third   ← first line duplicated
fixed:   first line\n  second line\n  third             ← no ^Y; byte-identical (p5)
```

There is **no cheap ring neutralizer**: `^U` on an *empty* composer does NOT scrub the ring on either TUI (`p4` still yanked despite the inject form's leading empty `^U`). The fix is structural — the multi-line/H path simply never sends `^Y`.

## Integration constraints (review round 3 — measured + code-verified)

1. **Every session starts `dirty/unknown` — fresh spawns and recovered sessions alike (rounds 3 → 9).** The recovered case: shellper-backed sessions survive a Tower restart (the TUI process — and any half-typed composer content — keeps living); the startup reconcile re-registers them as *fresh* `PtySession` objects, any in-memory `DraftTracker` is lost, and today `_lastInputAt` initializes to `0` (`pty-session.ts:98`), so a recovered session reports `isUserIdle() === true` immediately and a send delivers instantly onto a possibly-surviving draft. Round 9 closed the fresh-spawn hole the earlier rule left open: a newly spawned session is **not** born clean either — its boot screen is whatever the app renders first, and that is measurably an Enter-trap in real configurations (agy's per-folder workspace-trust dialog, `exp0c`; codex's `Press enter to continue` onboarding screen, which the POC's own `freshSession` helper has to dismiss on every spawn; claude's first-run flows). Initial state is therefore uniformly dirty; a session becomes deliverable only via the constraint-9 rendered proof (for known-profile apps this is quick — the first post-boot quiescence poll classifies the idle composer clean; unknown apps never converge, which is the defer-only + K posture arrived at independently). Input-only signals are insufficient in both directions: pre-restart menus/modals survive with the TUI, and boot screens precede any input at all.
2. **H requires the input gate** described in the delivery-matrix section (`i6a`: ungated byte applied twice; gated variant byte-identical). WebSocket frames must be divertible per-session for the duration of a maneuver, with a fail-open timeout. Round 5 generalized this: the gate is the divert mode of the per-session write transaction queue (constraint 7), not an H-only mechanism.
3. **E's flush must fire strictly *after* the user's Enter byte is written to the PTY.** The current handler tracks *before* `session.write(data)` (`tower-websocket.ts:92-101`); a flush triggered synchronously from that spot writes the message ahead of the user's `\r`, and the user's own Enter then submits the blob — measured: `wrduvq[architect] wrongorder` rendered as ONE transcript entry (`i6b` wrong-order). Writing the message after the `session.write(data)` call is sufficient (PTY fd writes are FIFO): the correct ordering delivered the draft as its own separate entry with no concatenation (`i6b` right-order, `e1`).
4. **Enter does not prove an empty (or even known) composer.** Measured divergences: (a) claude, "/" menu open — bare `\r` submitted the menu *selection* `/afx` while the captured buffer held `/` (`i6c`); (b) codex, "/" menu open — bare `\r` opened a **full-screen model-picker modal**; injected bytes would land inside the picker (`i6c`); (c) claude **restores queued messages into the composer on ESC** — content re-entered the composer with no input frame carrying it (observed during `i6a` setup); (d) codex's own UI tip: ESC on an empty composer enters "edit your last message", where "Enter confirms". Consequence for H: a missed or misclassified submit leaves a stale capture buffer, and a later max-age maneuver would clear an unknown composer and **replay already-submitted content**. Rule: frames that can open menus/modes (leading `/` on an empty buffer, ESC, Up/Down, Ctrl+G, Tab, unrecognized CSI, codex `\`+`\r`) mark the session **dirty**; while dirty, H and I are forbidden — defer, then **K at max-age**. Dirty clears only on the constraint-9 convergence proof (rounds 7–8: an output-side rendered-empty confirmation, keystroke-optional).
5. **Programmatic writers bypass tracking — and cron bypasses even today's defer.** `tower-cron.ts:303-323` writes cron messages straight to the PTY with no idle check and no SendBuffer; a `noEnter` delivery (`/api/send`, `tower-routes.ts:1586`) intentionally leaves unsubmitted text in the composer that no WebSocket frame ever carried; the `interrupt`/`escape` paths write control bytes directly. Round 9 completed the inventory with two more: **`POST /api/terminals/:id/write`** (`tower-routes.ts:902`, Spec 0104) is an arbitrary-byte HTTP write route — classify its frames as user-input-equivalent (they feed the tap like WS frames, pass through when the write queue is idle, divert during transactions); and **`afx reset`** orchestrates a multi-step sequence *through* Tower's routes (ESC via the escape route, `--raw '/clear'`, then reorientation sends — `commands/reset/`). Each reset step is individually a queue transaction, but the sequence as a whole is client-side and quiescence-gated, not write-layer-atomic; a held row draining at the post-`/clear` clean moment can legitimately precede the reorientation send — an ordering consideration for the implementation spec, not a corruption risk. Occupancy tracking therefore cannot live in the WebSocket handler alone — **hoist the tap to the single choke point, `PtySession.write()`**, classifying all inbound bytes regardless of writer. `noEnter` text then lands in the capture buffer (correct occupancy *and* replayable); cron must additionally route through the same defer pipeline as `handleSend`.
6. **K's substrate does not exist yet — a "safe fallback" that drops messages is not safe.** Code-verified (round 4): `broadcastMessage` iterates live in-memory WS subscribers and silently drops on failure; nothing in the repo consumes `/ws/messages` outside e2e tests; there is no messages table in `global.db`; `SendBuffer` is in-memory (held messages die with a Tower crash) and its `stop()` **force-flushes everything on graceful shutdown** (`send-buffer.ts:76`) — i.e., today a restart force-injects buffered messages regardless of typing state. K therefore requires: (a) a **persisted mailbox** (new `global.db` table) written *before* `afx send` responds; (b) a **default visible surface** — dashboard/VSCode "message waiting" indicator and/or an `afx inbox` CLI — not just a broadcast; (c) **enqueue-time persistence with a synchronous vocabulary the response can honestly keep (round 8)**: escalation happens up to 60 s *after* `afx send` returns, so "held" cannot mean "escalated" in the synchronous reply. The response reports only what is true at response time — `delivered` (bytes written now) or `held` (persisted row, id returned) — and **every deferred message is `held` from t0**: the in-memory `SendBuffer` queue and the mailbox collapse into one persisted store (a deferral *is* a hold; this also removes the crash-loss of buffered messages). Max-age escalation becomes a **visibility transition on the already-persisted row** (quiet-hold → surfaced), a later clean-line flush resolves it to delivered, and the **asynchronous outcome** is queryable by row id (send `--wait` flag, inbox/status route, broadcast event) — which is how porch/cron distinguish eventual delivery from persistent escalation; (d) shutdown behavior that persists held messages instead of force-injecting.
7. **No cross-writer serialization exists at the write layer — the H input gate must generalize to a per-session write transaction queue (round 5).** `writeMessageToSession` schedules its bytes with bare `setTimeout`s; its `delayOffset` parameter exists precisely to serialize consecutive messages, but the only caller that passes it is `SendBuffer.flush`, within a single batch (`tower-routes.ts:120-124`). The direct-delivery path in `handleSend`, cron's `deliverMessage`, and `writeEscapeToSession` (ESC now, `\r` 50 ms later) all schedule at offset 0 on the same session, and `handleSend`'s interrupt prelude (`^C`, 100 ms wait, then the message) is open to the same windows. Measured against the real module (`w1`, unit level): two concurrent short sends produce `msg1msg2\r\r` — the receiving line submits both as one blob (`w1a`); two concurrent paced multi-line sends interleave line-by-line `A1,B1,A2,B2,…` (`w1b`); a send arriving during an escape lands between the ESC and its trailing Enter (`w1c`); offset-chaining does serialize when actually used (`w1d`, control). This is a **today-bug reachable with no user draft at all** — two builders finishing simultaneously and both `afx send`-ing the same architect can blob — and it means the fix cannot be an H-specific gate: **every multi-step write sequence (direct send, buffered batch, cron delivery, escape/interrupt, E's flush, H's clear→inject→replay) must run as a transaction on one per-session FIFO queue with completion-based chaining** (the timing-based `delayOffset` scheme retires). User input frames pass through untouched while the queue is idle — zero added latency on the human path — and are diverted-then-appended while a transaction is active (`i6a`'s gate, generalized to all transactions, same fail-open timeout). E's ordering constraint (3) becomes a structural property of the same queue: the flush transaction enqueues behind the in-flight user write instead of relying on call-site discipline. **The queue is FIFO with a preemption lane, not a strict FIFO (round 8):** a strict FIFO would park `afx interrupt` behind an in-flight transaction — up to ~2 s behind an H maneuver — contradicting the interrupt's own design contract, stated in the code it would replace: "an interrupt that can be deferred because someone recently typed in this terminal is not an interrupt" (`tower-routes.ts:1501-1506`, which today handles `escape` *before* the buffer on purpose; the queue must preserve that property, not regress it). Interrupt/escape transactions therefore **preempt**: they abort any in-flight *preemptible* transaction at its next chunk boundary and run immediately. Abort semantics are per-type and never silent — an aborted H maneuver resolves through its journal (constraint 8: the journaled draft surfaces as a held recovery entry; no replay onto the post-interrupt screen, and the session is dirty anyway since ESC is a suspect frame); an aborted paced delivery re-holds its unwritten tail as an escalated mailbox row while the already-written prefix stays tracked as composer occupancy (the human who interrupted is looking at that screen — a visible partial plus a visible held remainder is honest; silently completing the delivery behind their interrupt is not). Only single `write()` calls are non-preemptible, and those are atomic by construction. **The preemption lane is itself serialized (round 9)**: lane entries run one at a time, FIFO, and an interrupt request arriving while an identical interrupt transaction is in flight **coalesces** into it instead of firing again — unserialized preemptors would re-create the #1264 double-`^C` hazard in Tower's own hands (the `--interrupt` prelude writes `^C`, `tower-routes.ts:1562`; `^C` on an already-empty claude composer arms exit and a second one kills the agent — which is also precisely the deliberate-exit gesture that lands the session on the constraint-10 wrapper prompt). The `--interrupt` `^C` prelude is a lane transaction like the escape route's ESC.
8. **H destroys the only durable copy of the draft mid-maneuver — journal it, and classify H best-effort (round 6).** The maneuver's first act (per-line clear) erases the draft from the TUI while the only replay copy sits in Tower memory. Shellper's crash-persistence then works *against* the user: the TUI — with its now-empty composer — survives a Tower crash, but the capture buffer does not, so a crash or fail-open gate timeout between clear and replay loses the draft outright. Collapsing the maneuver into one atomic write is not an available escape: the sequence is inherently multi-**step** — clear, inject, replay must remain separate writes with verify settles between them (the one fully-atomic form tried on claude **submitted the draft**, `i3`, bracketed) — though round 9 collapsed each *step* to bulk writes with per-app O(lines) fallbacks at size (`i7`), making the window ~1–3 s for typical drafts and specifiable as f(app, lines) at the cap (under round-8 char pacing it scaled to ~2 min at 8 KB, which made the fail-open timeout unspecifiable). Required consequences: (a) **journal the capture buffer to durable storage before the first destructive byte** — a tiny write, the buffer is capped at 8 KB; the journal is *not* a log: a transient row deleted on successful replay, stored with the same privacy posture as mailbox content (draft bytes still never appear in Tower logs); (b) on crash or timeout mid-maneuver, the recovered session starts dirty (constraint 1) and the journaled bytes are **surfaced as a held draft-recovery entry** — never auto-replayed onto an unknown composer; (c) **H is best-effort by classification**: its worst case is "composer copy lost, bytes surfaced", never silent loss — and **K remains the no-risk path**; any doubt (dirty state, journal write failure, queue contention) resolves to K, not H.
9. **The rendered-empty proof is the universal pre-delivery gate — convergence out of `dirty` is one use of it, and it requires NO keystroke (rounds 7–9).** Round 7 defined convergence as "user submit + rendered-empty confirmation"; round 8 showed that gating on a *user submit* deadlocks every builder terminal (no human typist — sessions go dirty on `afx interrupt`, `afx reset`, or any Tower restart, and a keystroke-gated convergence never fires), so the definition inverted: **the rendered proof IS the convergence; a user submit is merely one trigger for running it.** Round 9 then withdrew the round-7/8 scope note that exempted tracked-clean sessions: the launch-loop wrapper (constraint 10, `i8`) can swap the process behind the PTY with **zero input frames** — an input-side model can be perfectly maintained and still describe a screen that no longer exists — so **every delivery write (direct, E-flush, drain, maneuver entry) is preceded by a G-lite rendered-empty check**, at a measured cost that makes this a non-event: **2 ms at 13 KB, 22 ms at 1 MB (= `RING_SEED_MAX_BYTES`, the production seed cap, `tower-terminals.ts:38`), 67 ms at 4 MB** (a live ring's unbounded partial can exceed the cap, #1047 basin). Input-side tracking remains the *scheduling* signal (defer/flush timing, per-keystroke, free); the rendered check is the *final gate* (per-delivery, ~tens of ms). Residual race, stated: a process exit landing inside the check→write gap (sub-second) is not closed; the `^C`-on-empty dirty rule (classification table) covers the deliberate-exit gesture input-side, and crash exits print wrapper output that the next check sees. Dirty→clean fires when the classification returns provably-empty: composer marker present AND zero normal-intensity, non-whitespace cells in the composer region. Both TUIs render their rotating placeholder text **SGR-dim** while user text is normal-intensity (`g2a`/`g2f`; four distinct codex placeholders classified clean in one round-9 run) — no placeholder allowlist to rot — and the check fails toward dirty on anything unrecognized. The two tripwires are independent (round-9 mechanism correction): codex's full-screen model picker in fact FINDS a marker (its rows carry `›`-prefixed selection lines) and fails on **116 normal-intensity cells** (`g2j`), while agy's screens fail on **no marker** (`exp0c` — and agy's hint text is *normal-intensity*, so even a naive marker addition would fail-toward-dirty; the dim-placeholder rule is per-app measured fact, not universal law). **Classifier profiles are per-app data, and the liveness failure mode must be designed for (round 9)**: the marker regex and region bounds are verified-app profile entries keyed by the same strict app-identity table as the delivery matrix (the POC's `gpt|high:|~\/` bounds are POC-grade stand-ins), version-pinned and re-verified by the smoke suite; a TUI/config drift that breaks the profile makes every session permanently dirty — **fail-toward-held, never corrupt, but a liveness regression**: all polite sends to that target hold forever, and before phase 3's inbox the only surfaces are the `held` response, log, and broadcast. Required mitigation in phase 1: **classifier-health telemetry** — a session with recent output whose checks return no-marker/not-clean N consecutive times while its tracker sees no occupancy raises a loud diagnostic (ERROR log + broadcast + reason on the held rows/responses), so profile drift is an alarmed event, not a silent stall; `--interrupt` and phase 3's "deliver now" remain the human bypasses. Triggers for the check: (a) a submit-classified user bare-`\r` — human terminals, event-driven; (b) **the drain poll after output quiescence (~2 s settle)** — automated terminals, no keystroke involved (validated shape: every `g2` verdict was produced from ring-replay data alone on a quiescent screen, zero input frames consumed); (c) an explicit human act. The production data path is exactly the reconnect replay: `ringBuffer.getAll().join('\n')` (`tower-websocket.ts:66-67`) written into a **transient** `@xterm/headless` instance (pinned dep; 6.0.0 in the POC), disposed after the check — validated on **both TUIs** (round 9 completed the codex arm) for idle-empty, drafts, menu-with-filter-text, churned streams, **arbitrary mid-byte truncation** (the `capRingSeed` cut), and **resize-nudge fresh frames in both the draft and the empty-composer variants** (`g2e`/`g2e2`/`g2k`/`g2l` — the empty variant is the actual production convergence shape; the nudge is occupancy-neutral on both TUIs and is the bounded-cost path for long sessions: on-demand per convergence attempt with a minimum interval, never a periodic tick). Stream-shape, measured: claude emits **no newlines at all** (`g2d` — everything accumulates in the unbounded `partial`; the byte cut is the real truncation), codex produces a mixed lines+partial stream (`g2m`: 16 lines + 17 KB partial); both reconstruct correctly. Residual, stated honestly: an armed mode that captures Enter while rendering *nothing* (or only dim chrome) would defeat the classifier. Measured on codex 0.146: ESC on an empty fresh session produces **no rendered change** (`g2h` — which proves no *visible* signature, NOT that no invisible mode was armed; the assertion is now two-sided, so any future codex that renders an ESC signature fails the suite loudly); the dangerous codex states (model picker, edit picker) render loud → not-clean; the *with-history* single-ESC case is analytically a hint rather than an Enter-capturing mode, but is unverified on a real account — flagged in Next Steps. Full output-stream line modeling stays out of scope.
10. **The builder launch-loop wrapper is a silent-loss path that no input-side model can see — measured (round 9, `i8`).** Every builder terminal runs `.builder-start.sh`: `while true; do <agent>; …; done` with the shared `LAUNCH_LOOP_TAIL` (`spawn-worktree.ts:798`, five generation sites — architect sessions restart Tower-side via `PtySession` respawn machinery and do NOT have this wrapper). Two wrapper states own the PTY's stdin with no agent behind it: **(a) deliberate exit** (status 0) — bash `read -r` waits on "Press Enter to relaunch". Asserted end-to-end with the *production tail extracted from source at runtime*: a Tower-shaped delivery (text, `\r` at 50 ms) onto that prompt is consumed by `read` — the text is discarded into `$REPLY`, the `\r` terminates the read, **the agent relaunches as a side effect of the delivery**, and a drain-probe on the successor agent's stdin finds nothing (`i8a`, four assertions). The sender was told "delivered". **(b) crash restart** (status ≠ 0) — bash sleeps 2 s then relaunches; bytes sent into that window are drained by the *booting successor*: measured with real claude, the message lands **in the fresh composer as unsubmitted text** — the `\r` never fired as a submit (`i8b`) — i.e. composer contamination plus a model/reality divergence (the tracker would have classified the delivery's own `\r` as a submit and modeled the line empty while the real screen kept the text). Both states are invisible to input-side tracking: state (a) involves zero input frames before the delivery, and in state (b) the delivery's own frames mis-model because app *boot* semantics differ from steady-state. Both are caught by the constraint-9 pre-delivery gate: neither the wrapper prompt, the restart countdown, nor a mid-boot screen contains a profile composer marker → not clean → held. This is what turns K's "never silent loss" from a slogan into a property — without the gate, the wrapper eats messages while reporting success; today's `shouldDefer` (idle-timer only) delivers into both states freely.

## Max-age semantics: noEnter and K drain (round 5)

Reviewer question: what happens to a `noEnter` message at max-age, and how do K-held messages ever reach their target?

**Today (code-verified).** At max-age — or shutdown force-flush — `deliverBufferedMessage` writes a `noEnter` message's text into the composer with no occupancy check (`tower-routes.ts:120-124`, `send-buffer.ts:116-131`). It submits nothing, but it silently contaminates whatever draft is on the line. Two loss paths sit next to it: buffered messages for a session that disappears are **discarded** with a WARN (`send-buffer.ts:86-92`), and messages for an unwritable session at max-age are **dropped** with an ERROR (`send-buffer.ts:103-110`). Together with `stop()`'s force-inject (constraint 6d), that is four paths where today's pipeline corrupts or loses rather than holds.

**noEnter policy.** A `noEnter` delivery is composer-mutating by design — it stages text for a human to edit and submit — so it is *never* injectable onto a non-empty or dirty line, and H cannot rescue it: there is nothing to submit, and replaying the draft after staging text would merge the two (both want the same composer). Rule: **noEnter + occupied/dirty at max-age → K-hold; no injection form exists for it.** On drain (line provably empty) the text is written without Enter; the staged text immediately registers as occupancy via the `PtySession.write()` tap (constraint 5), so any subsequent message — noEnter or not — defers behind it exactly like a user draft, ages out, and K-holds in turn. No second special case is needed.

**K drain/retry semantics (the eventual-delivery machinery).**
1. **Mailbox rows address agents, not PTYs**: keyed `(workspacePath, agent)`, with the terminalId recorded as a hint only. A respawned terminal for the same agent drains its predecessor's held messages; messages outlive sessions — the discard-on-dead-session and drop-on-unwritable paths above become *held*, not lost.
2. **Drain triggers**: (a) for dirty sessions, the constraint-9 convergence proof (rounds 7–8 — its quiescence trigger means builder terminals drain without a human keystroke); for tracked-clean sessions, E's flush moment; (b) the periodic poll as backstop; (c) recovery convergence after a Tower restart (rows are already persisted; constraint 1's recovered-dirty state converges first, then drains). Drain is oldest-first and runs **ahead of** younger `SendBuffer` entries for the same target, preserving per-target arrival order.
3. **Drain mechanics**: each drained message goes through the normal delivery pipeline — a transaction on the per-session write queue (constraint 7) with the constraint-9 rendered-empty gate re-run at drain time (round 9: the gate, not just the input-side occupancy model — a drain can otherwise fire into a wrapper prompt, constraint 10). If the check fails, the remainder stays held: it is already escalated and visible, so there is no re-escalation churn and no timer reset.
4. **Retention**: held messages persist until delivered or explicitly dismissed from the inbox surface (dismissal recorded as acknowledged-out-of-band). No TTL, no silent expiry.
5. **Sender semantics**: `afx send` returns `held` (with the mailbox id) vs `delivered` (constraint 6c). `held` is the enqueue-time answer for every deferred message — the sender learns the *final* outcome (delivered on a later flush vs escalated at max-age) asynchronously, by row id, because that outcome does not exist yet when the response is written (round 8). Today's response shape already concedes this: `handleSend` returns `deferred: boolean` and nothing ever reports what became of a deferred message.
6. **Recurring automated senders coalesce (round 8)**: with cron rerouted through the pipeline (phase 1) and holds retained until delivered, a recurring `${output}` snapshot against a perpetually occupied/dirty target would accumulate one held row per firing and later drain as a burst of stale snapshots. Machine senders therefore stamp a **supersede key** (cron: the task id); enqueueing with a live key **replaces** the older held row — recorded on the row (supersede count, first-held timestamp) and in the cron run log. This is explicit replacement of a superseded snapshot by its newer version, not silent expiry; the no-TTL rule for human messages is unchanged, and drain bursts are bounded to one row per key. Cron's run record gains the delivery outcome (`delivered` | `held(id)` | `superseded(id)`) — today `deliverMessage` is fire-and-forget: the run is recorded off the command result alone, "delivered" is logged unconditionally on the write path, and the target-gone/session-gone paths WARN-and-drop (`tower-cron.ts:303-323`). The reroute turns those drop paths into holds and makes the log honest.
6. **The honest guarantee**: a held message reaches the composer at the first drain attempt that finds the line provably empty; if the line never empties, it remains persistently visible in the inbox — *eventual delivery or persistent visible escalation, never silent loss*. A hard composer-delivery guarantee is impossible without re-introducing forced injection onto an occupied line, which is the exact corruption this spike removes. `--interrupt` sends remain the explicit, human-invoked exception that bypasses deferral entirely.

## Constraints discovered

- **The per-line clear and the trailing `^Y` must never appear in the same sequence.** The clear primes the kill-ring with the first draft line (bottom-up kills, overwrite semantics, both TUIs), a later `^Y` yanks it back ahead of the replay, and no injectable primitive scrubs the ring (empty-composer `^U` doesn't). Duplication measured on both TUIs (`p4`); details in "Kill-ring interaction" above.
- **Per-app divergence is real and version-sensitive — and the delivery-form keying needs its own substrate (round 9).** The bracketed/unbracketed atomicity split (i3 vs i2a) is the sharpest example. Tower knows the configured agent command per terminal, but **the existing harness resolver must NOT be the key**: `detectHarnessFromCommand` (`harness.ts:329-342`) matches only claude/codex/gemini/opencode basenames — `agy` matches nothing (its basename does not contain "gemini") — and `resolveHarness` **falls back to `CLAUDE_HARNESS`** when detection fails (`harness.ts:391-392`); the `config.ts:256-278` citation rounds 8 used is the *JSDoc* on `getArchitectHarness`/`getBuilderHarness`, not detection logic. Keyed on that resolver, an agy terminal IS a claude terminal and gets claude's atomic form. The delivery matrix therefore needs a **strict app-identity table**: verified apps (claude, codex) matched exactly, everything else a first-class `unknown` that maps to defer-only + K — a fallback-to-claude is a correctness bug here even though it is the right behavior for the resolver's own job (role injection). Keep the POC harness as a smoke-test to re-verify the matrix when agent versions bump (exercised in round 8: codex bumped 0.145→0.146 mid-spike; the full asserted suite re-ran green — and again in round 9 across the extended suite).
- **agy (Antigravity CLI) is a configurable send target TODAY; its trust dialog is per-folder, and its UI breaks both classifier assumptions (rounds 8–9).** Round 8 observed the fresh-spawn **workspace trust dialog** — "enter Confirm" on "Yes, I trust this folder", typed text not rendering — so a blind text+`\r` delivery would confirm a filesystem-trust decision as a side effect. Round 9 re-ran after the architect trusted this workspace (`exp0c`, agy 1.1.8): the dialog is gone *for this folder* — agy now renders a normal composer (`> ` marker, typed text visible, `^E ^U` clears the line) — but trust is granted per folder (the dialog names the path), so **every fresh worktree is a fresh Enter-trap**; constraint 1's sessions-start-dirty rule is what protects builder-agy spawns. For G-lite: agy's `>` marker does not match the `^[❯›]` profile (never classifies clean → automatically held), and its hint text renders **normal-intensity** (`dim=0`) — unlike claude/codex's dim placeholders — so the dim-placeholder rule is per-app measured fact, not a universal law; an agy profile requires its own onboarding through the matrix. Until then agy stays defer-only + K by mechanism, not just policy.
- **Ctrl+C is not an injectable clear**: on an empty claude composer it arms "press again to exit" — an injected Ctrl+C adjacent to a user's own could kill the agent (cf. regression #1264). Ctrl+U/Backspace primitives are side-effect-free on both TUIs.
- **Ctrl+G opens `$EDITOR` on both TUIs** — any occupancy design must treat it as modal (set dirty, never clear).
- Codex leaves an **unrecognized `/slash` message in the composer** (with an error) instead of submitting it — a formatted afx message starting with `/` would strand. Current formats start with `[architect]`/`[builder]` so this is only a `--raw` edge; worth a guard.
- Bracketed paste is **not a control-char sanitizer** on claude (ESC inside brackets swallowed following chars, `j3`). Raw control-byte payloads stay on the existing `--raw`/escape path.
- Drafts built via Up-recall replay imperfectly (history mutates once the injected message submits). Edge case; acceptable — or treat nav-dirty drafts as K-escalation candidates.
- Tower must hold draft bytes in memory per session (privacy: never log them; cap the buffer, e.g. 8 KB, falling back to defer-only when exceeded).
- Multi-client sessions (dashboard + VSCode attached to one PTY) interleave input frames; the capture stream is the merged order the PTY itself sees, so replay fidelity holds.

## Recommended approach (confirms the issue's, with revisions)

1. **Core: A+E via a single `DraftTracker`, tapped at `PtySession.write()`** — not the WebSocket handler — so every writer (user frames, sends, `noEnter`, cron, escape) feeds the same occupancy model. Draft buffer + dirty flag; defer while non-empty/dirty; flush event the moment the buffer empties (bare-`\r` submit, Ctrl+C, Ctrl+U-to-empty), fired **strictly after** the triggering bytes are written to the PTY (`i6b` ordering constraint). Replaces `shouldDefer`'s timer-only check (`tower-routes.ts:1570`) and `SendBuffer`'s 500 ms poll (keep the poll as backstop; keep the 60 s max-age valve). Route cron's `deliverMessage` through this same pipeline **in phase 1** (round 7: leaving cron direct-writing would preserve a force-inject path the phase claims to remove). All delivery writers execute as transactions on the **per-session write queue** (constraint 7) with completion-based chaining — this alone fixes today's concurrent-sender blob (`w1a`) and retires the timing-based `delayOffset` scheme. The queue carries an **interrupt preemption lane** (round 8): escape/interrupt aborts an in-flight preemptible transaction at its next chunk boundary instead of queueing behind it — a strict FIFO would make the interrupt deferrable, which the current code explicitly forbids. The lane itself is serialized with coalescing of concurrent identical interrupts (round 9 — unserialized preemptors re-create the #1264 double-`^C` kill). **Every delivery write is preceded by the constraint-9 rendered-empty gate** (round 9, ~2–22 ms): input-side tracking schedules, the rendered check gates — this is what closes the launch-loop wrapper loss (constraint 10).
2. **Dirty-state machine**: modal/mode-suspect frames (leading `/` on empty buffer, ESC, Up/Down, Ctrl+G, Tab, unrecognized CSI, codex `\`+`\r`, and — round 9 — `^C` on an empty-model composer) mark the session dirty, and **every session is BORN dirty** — fresh spawns render onboarding/trust Enter-traps and recovered sessions may carry surviving drafts/menus (constraint 1); dirty forbids H/I injection outright. Converge to tracked only via the constraint-9 output-side proof (G-lite rendered-empty on the production ring-replay path, triggered by a user submit OR the quiescence poll — no keystroke required, so builder terminals converge too, and fresh known-app sessions converge on their first post-boot poll); otherwise K at max-age.
3. **Max-age path, multi-line drafts: H** — as a write-queue transaction in **divert mode** (user frames diverted for the maneuver's duration, appended after replay, fail-open timeout — specifiable as f(app, lines) now that every step is bulk or O(lines): ~1–3 s typical, `i7`), **journal-first** (constraint 8: capture persisted before the first destructive byte; crash/timeout surfaces the journal as a held draft): per-line clear (bulk ≤13 lines on claude, paced beyond; bulk on codex), per-app atomic inject **without the trailing `^Y`**, per-app replay (bulk on claude; bulk ≤~0.5 KB on codex, line-chunked beyond — its large single-write replay paste-collapses). The replay is the sole restore mechanism on this path. H is **best-effort**: any doubt resolves to K. **Build H behind the phase-2 gate** (round 9): its addressable population — linearly typed multi-line drafts on tracked-clean sessions — is narrow; ship the hold core first, record why-held metadata, and decide from field data.
4. **Max-age path, single-line drafts: I/B** — the per-app atomic kill/yank form (ends in `^Y`, no per-line clear, no replay). Keep the two paths non-overlapping: `^Y` restores, or replay restores — never both in one sequence (`p4` duplication).
5. **I/J forms**: per-app as specified — J's framing only where verified (codex, unknown-app semi-atomic); never in claude's atomic write.
6. **K is a required component, not optional hardening — and it must be built as a real mailbox**: persisted (`global.db` table, written before the send response), visibly surfaced (dashboard/VSCode indicator, `afx inbox`), with `held`-vs-`delivered` send-response semantics and persist-on-shutdown (integration constraint 6). It is what makes "when in doubt, don't inject" a safe default — a fallback that can silently drop messages is not a fallback. Drain semantics per the round-5 section: agent-keyed rows, clean-event + poll + recovery triggers, oldest-first ahead of the live buffer, occupancy re-checked at drain time, held-until-delivered-or-dismissed. Round 8 sharpens the substrate: **deferral is a hold from t0** — rows persist at enqueue and the in-memory `SendBuffer` queue collapses into the mailbox; the synchronous response speaks only enqueue-time truth (`delivered` | `held` + id) because max-age escalation happens up to 60 s later and is just a visibility transition on the persisted row; final outcomes are async by row id; machine senders coalesce via supersede keys. `noEnter` messages at max-age always K-hold (no injection form exists for them). **K's hold core ships in phase 1** (round 6): no phase may ever force-inject, so the persisted held store, `held` responses, drain-on-clean, and persist-on-shutdown are pulled forward — as is the **minimal cron reroute** (round 7); the visible surface and cron-specific inbox attribution complete in phase 3.
7. Retire #584 pacing for verified-current claude/codex once this ships (keep for unknown apps).
8. Ship the POC harness as a re-verification script for future TUI version bumps.

potentially skipped**), draft journal + maneuver-crash recovery surfacing (~70, constraint 8), K mailbox — DB table/migration with rows persisted at ENQUEUE (absorbing SendBuffer's in-memory queue), inbox routes, surfacing, `held`/`delivered` enqueue-time vocabulary + async outcome query/event, supersede-key coalescing, drain scheduling per the round-5 semantics, persist-on-shutdown, cron-specific inbox attribution (~420–520; the minimal cron reroute itself is a phase-1 item, ~55 incl. delivery-outcome recording in the run log), tests (~430+, incl. a keystroke-sequence unit suite derived from the classification table and the POC's asserted scenarios, wrapper-state delivery tests, and identity-table/profile-drift tests). Hooks sit at existing choke points (`PtySession.write`, `SendBuffer`, `handleSend`); the one genuinely new architectural element is G-lite's transient server-side screen reconstruction — Tower's first runtime terminal-emulator dependency (`@xterm/xterm` today is only a web-client devDependency), created per check and disposed, never a persistent per-session emulator. Rounds 3–9 (gate/dirty/recovery, cursor model, K-as-mailbox, write queue + preemption, journal, hold-first phasing, production-path G-lite, universal delivery gate, identity table) push the total past Medium if shipped monolithically.

**Phase it — and no phase may ever force-inject (round 6).** The original phasing was not independently *safe*: until K existed, max-age and `SendBuffer.stop()` would keep force-injecting, and the dirty / recovered / `noEnter` / unwritable / dead-session cases have **no safe injection form at all** — their only outlet is a hold. So the **minimal K hold core is pulled into phase 1** (persisted held store + `held`-vs-`delivered` responses + drain-on-clean-event/poll + persist-on-shutdown + hold-at-max-age for all no-outlet cases — a reallocation of the K estimate, not new scope), and so is the **minimal cron reroute** (round 7: `deliverMessage` → the shared deliver-or-defer pipeline; leaving cron direct-writing would preserve exactly the force-inject path the phase claims to remove). The visible inbox surface and cron-specific inbox attribution complete in phase 3. Interim visibility before phase 3 is the sender's `held` response, the Tower log, and the existing broadcast — acceptable *as an interim* because nothing is dropped (rows are persisted and drain automatically on the next clean event); the pathological "user never empties the line" tail waits visibly for phase 3's inbox instead of being corrupted as today. Revised phases, each an independently shippable Medium: **(1) safe core** — A+E DraftTracker write-tap + cursor model + submit-detector + defer/flush rewiring + write transaction queue (incl. the serialized/coalescing interrupt preemption lane — a strict FIFO would regress `escape`'s handled-before-the-buffer contract, and unserialized preemptors would re-create #1264) + dirty machine (incl. **born-dirty for every session** — fresh and recovered, round 9) + **G-lite as the universal pre-delivery gate** with the no-keystroke quiescence trigger, per-app classifier profiles, and drift-health telemetry (without the gate phase 1 still has the wrapper silent-loss path, `i8`; without the telemetry a profile drift silently converts all traffic to held-forever, round 9) + **strict app-identity table** (unknown → defer-only + K; never the resolver's claude fallback) + minimal K hold core (**enqueue-persisted from t0** with `held`/`delivered` responses, async outcome query, supersede-key coalescing, **why-held metadata** — it feeds the phase-2 H gate) + minimal cron reroute (incl. delivery-outcome recording): kills the common-case corruption, today's concurrent-sender blob (`w1a`), the wrapper eat-and-relaunch path, and **every message force-inject path** (the explicitly-destructive human interrupt — `--interrupt` / `afx interrupt` — remains by design); **(2) delivery quality** — per-app atomic forms + single-line I/B path + draft journal, all under the queue's divert mode; **H specifically sits behind a build/skip decision gate** fed by phase-1 why-held data (its addressable population — linearly typed multi-line drafts on tracked-clean sessions — may be too thin to justify ~220 LOC of maneuver+journal); **(3) K surface + integrations** — inbox UI/indicator/`afx inbox`, outcome events/`--wait`, cron inbox attribution, drain-order refinements, #584 pacing retirement.

## POC methodology (revised after round-4 and round-5 reviews)

**Round 4.** A reviewer rerunning `exp-i6-gating.cjs` got `i6a-gated-clean=false` with exit 0 — a fair hit on the original methodology: verdicts were printed, not asserted, and that particular false-FAIL came from a cross-demo contamination (i6b's dead-API retry queue + claude's ESC-restores-queued-messages behavior polluted i6a's reference draft, while the gated run itself was correct against its own rebuilt draft). Fixes applied:

- **Two evidence tiers.** `exp0`–`exp-i4` and `exp0c` are *exploratory* (observation prints; they discovered the behaviors). `exp-a3`, `exp-i5`, `exp-i6`, `exp-w1`, `exp-g2`, `exp-i7`, and `exp-i8` case A are *regression-grade*: every claim is an `ASSERT` with an expected value and any failure exits non-zero (`i8` case B — where crash-window bytes land in a booting TUI — is measured, not asserted). The isolation guarantee is **scoped per suite** (round 8 corrected an overclaim here): fresh-session-per-demo (`i6`), fresh-session-per-case (`a3`, `g2`, `i7`), or single-session-by-design with fail-closed exact-equality oracles (`i5`, a sequence test).
- **Content-based checks, never chrome-based.** "Composer empty" is asserted as "does not contain the known injected draft string", because both TUIs rotate placeholder text (a codex placeholder not in an allowlist produced a false FAIL during hardening; `def` ⊂ "default" was a latent collision — draft strings are now collision-proof).
- **Retained evidence.** The asserted suite's full stdout is committed under `1265-poc/results/` (one file per experiment × TUI, all `ALL ASSERTIONS PASSED`/exit 0), and every screen snapshot lands in `EVIDENCE_DIR` at run time.
- **Honest residual**: driving live TUIs is inherently timing-sensitive; the suite mitigates with output-quiescence settles and content assertions, and rerunning `results/` is the smoke-test for future TUI version bumps (recommended-approach item 8).

**Round 5 — the i6b flush-ordering demo needed the same medicine.** A reviewer's two fresh reruns of the claude suite failed. Local reproduction attempts — 5 whole-suite runs plus 8 isolated runs of the original i6b, 13/13 exit 0 — never hit the exact failure, but they showed *why* the reviewer did: **in every one of the 13 runs the right-order case executed inside queue-contaminated state** (the composer extraction returned claude's "Press up to edit queued messages" hint, and the `!includes('def')` assertion passed only because that hint text happens not to collide). The pass was assertion-weakness, not clean behavior; which basin the timing lands in is machine-dependent, and the reviewer's machine lands the same contamination where the assertion breaks. Structural causes, all previously-measured behaviors: (a) i6b's two cases shared one dead-API session, and the wrong-order case leaves it retrying with queued content; (b) the inter-case ESC ESC is exactly the gesture that interrupts an in-flight retry and restores queued/interrupted content into the composer (constraint 4c); (c) the Up-recall assertion reads per-project history — shared with any *other* claude session running in this repo (a reviewer rerunning the suite from their own claude session qualifies, as does the builder's) — and queue state repurposes Up ("press up to edit queued messages"). Fixes: **i6b split into two fresh-session cases; Up-recall and the inter-case ESC are gone.** Both cases now assert on the *transcript* — a submitted message renders as its own conversation entry, so the blob check is "the concatenated string appears as one entry" and the clean check is "the draft appears alone, no concatenated entry exists" (the pattern i6c already used) — with collision-proof tokens (`wrduvq`, `rtdkzp`). Post-fix: **5/5 consecutive claude suite runs pass (11 assertions each) and the codex run passes**, exit 0 throughout; the committed `.out` is run 5. The round-4 "6/6 runs exit 0" claim was too strong — true of the runs made, but the right-order case was passing for the wrong reason; reproducibility statements are now scoped to the committed suite on this machine, with the suite itself as the portable re-verification.

**Round 8 — isolation claims corrected; suite re-versioned.** A reviewer caught the tier bullet overclaiming "each demo runs in its own fresh TUI session with per-demo baselines": true of `exp-i6` but not of `exp-a3` (three independent probes in one session, with `^E ^U` — a3c's own subject primitive — as the inter-case cleaner) or `exp-i5` (p1–p5 in one session, p5 asserted against p1's snapshot). Resolution by kind: **`a3` was restructured to a fresh session per case** (no inter-case cleanup left to be imperfect) and re-run green on both TUIs. **`i5` stays single-session BY DESIGN and is now labeled what it is — a sequence test**: its subject is a stateful multi-step maneuver whose kill-ring carry across phases *is* the bug under test. What separates it from the round-4/5 contamination pattern is failure direction: its terminal assertions are exact-equality against the in-session baseline, so inter-phase residue makes p4/p5 **fail loudly**, where the round-4/5 flakes were fail-open `!includes` checks passing silently on contaminated state. Round 8 also added assertions on the previously snapshot-only intermediate cleanups (`p3-cleaned`/`p4-cleaned`), so a dirty hand-off is caught at the hand-off. **Version note:** codex bumped 0.145.0 → 0.146.0 between rounds 5 and 8; the full asserted codex suite (`a3`, `i5`, `i6`, `g2`) was re-run green on 0.146.0 — recommended-approach item 8's version-bump smoke-test exercised in anger, no divergence found. Claude stayed 2.1.212.

**Round 9 — two fail-open assertions closed; coverage completed; substrate pinned.** (a) `a3c`'s clear verdict was an **unanchored** `!includes` — the round-8 isolation restructure had removed any proof that the composer extraction ever saw the draft in that session, and the committed evidence shows the "cleared" screen was claude's rotating placeholder (which passes `!includes` vacuously). Fixed by anchoring: the same extraction must return exactly `uvwxyz` *before* the clear (`a3c-anchor-draft-visible`), re-run green on both TUIs. (b) `g2h`'s consistency check was `changed ? true : clean===true` — structurally unfailable on the changed branch. Now two-sided (unchanged ⇒ clean, changed ⇒ NOT clean), so a future codex that renders any ESC signature fails the suite loudly: a real version-bump tripwire, at the cost that a benign dim-only signature also fails and forces re-analysis — the correct trade for a smoke test. (c) The codex evidence arm was completed: `g2` grew from 7 to 25 codex assertions (menu, full-screen model picker — the previously *uncovered* marquee case —, nudge-draft, nudge-empty, churn + byte-cut), `g2e2` added claude's empty-composer nudge (the actual convergence shape), and the doc's per-TUI coverage claims now cite what ran where (`i6` remains 11 claude / 2 codex assertions by design — its `i6a`/`i6b` demos need the dead-API submission rig). (d) The render substrate is pinned: `@xterm/headless` 6.0.0, printed by the harness into every `.out`, so the suite's own dependency is part of the version-bump story it exists to smoke-test. (e) A settle-race in the new `i7` harness was itself root-caused mid-round (quiet-period settling can return before a bulk write's effect paints — the timestamp it tests is stale after a quiet snapshot); the maneuver steps now use condition-based waits (poll for the expected screen state, bounded), which also yields honest step timings.

## Flaky Tests

None in repo test suites (the spike ran none). Two POC flakes existed, both root-caused to the same mechanism (dead-API retry/queue state interacting with claude's restore-on-ESC and history keys): round 4 — the original single-session `exp-i6` let queued-message restore contaminate a later demo's baseline (fixed by per-demo session isolation); round 5 — the i6b flush-ordering demo still shared one session between its two cases and asserted via Up-recall (fixed by per-case session isolation + transcript-based assertions; see POC methodology). Round 9 added a third, different in kind: quiet-period settling in the new `i7` harness could sample the screen before a bulk write's effect painted (stale-timestamp race → false FAIL on a real behavior boundary); fixed by condition-based waits (see POC methodology, round 9e).
