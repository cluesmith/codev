## Implement phase_2 (2026-11-17)
The claude lane runs `claude -p` from the installed CLI. No SDK import is left in `consult/`; `doctor.ts` keeps its import until phase_3.
- argv (`buildClaudeReviewArgs`): `-p --output-format stream-json --verbose --tools Read,Glob,Grep --permission-mode dontAsk --allowedTools Read,Glob,Grep --setting-sources "" --strict-mcp-config --disable-slash-commands --no-session-persistence --max-turns 200 --max-budget-usd 25 --model <id> --system-prompt-file <0600 file in the sandbox dir> --add-dir <sandbox dir>`. The prompt goes on stdin.
- Stream reader: every stdout line must be JSON. The init guard requires the `system/init` tools ⊆ Read/Glob/Grep, with no assistant event before init. Any mid-stream failure SIGTERMs the child (SIGKILL after 5s) and awaits its exit before rejecting.
- Classification order: no result (exit ≠ 0 / exit 0) → "Prompt is too long" (context-exhaustion message naming the model and #1641) → error subtype → `is_error` → non-zero exit after success. `is_error` is checked before a `success` subtype is trusted.
- Signals: SIGINT/SIGTERM handlers registered only around the lane. They terminate the child, wait for its exit, remove the temp file and any stale `--output`, then exit 130/143 with no metrics row. They are removed in `finally`; tests assert no listener leak.
- Added beyond the plan: the result's `permission_denials` are named on stderr (`[CLAUDE] warning: claude denied N tool calls …`). Under `dontAsk` a denied read is otherwise silent, which is the spec's "PR reviews run blind" risk.
- Tests: new `claude-cli-lane.test.ts` (46 tests). Migrated `consult.test.ts`, `bugfix-1754`, `lane-models` and `tripwire-wiring` (the stub's new `beforeOutput` shell hook plays a mutating lane). ### Release note (draft for the PR body, ready to paste)
**consult: the claude lane now runs your installed `claude` CLI, on your subscription (#1912).** `consult -m claude` no longer uses the bundled Claude Agent SDK. It runs the `claude` on your `PATH` (2.1.141 or newer, or `CODEV_CLAUDE_BIN`) in read-only print mode, so upgrading `claude` upgrades the lane. It uses the CLI's own login by default, which for most people is the Claude subscription. `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` are withheld from it, whether set in the shell or in the workspace `.env`, and the `[CLAUDE] auth:` line says when a key was ignored. **Breaking for key-only environments:** a CI job with `ANTHROPIC_API_KEY` and no `claude` login now fails loudly. To keep billing the API, add `"consult": { "claudeAuth": "api-key" }` to `.codev/config.json`. `codev doctor` now checks the installed `claude` version and login, with no model call. The `@anthropic-ai/claude-agent-sdk` dependency is removed. The test-only opt-in `CODEV_ALLOW_REAL_CLAUDE_SDK` is renamed `CODEV_ALLOW_REAL_CLAUDE`.
